# 跨领域 100 包测试协议（2026-09-16，运行前冻结）

## 目标与计数

本轮测试的是产品参数证据系统，不是证明模型达到某个总体正确率。
交付 100 个可单独运行、可追溯的资料包，覆盖 10 个领域：工业电源、网络设备、
机械传动、电池储能、散热通风、光伏、环境传感、电动工具、胶粘材料、计量仪器。

- 20 包：厂商公开资料的参数选摘、翻译或格式改编，保留原始 URL、型号和适用条件。
- 80 包：参考这些领域设计的虚构商品/脱敏压力场景，各自有不同的参数组合、
  输入结构或业务风险。不是改几个数字后重复计数，也不是 80 份真实客户材料。
- 原始 PDF 通路验证另行统计，不把同一包换格式、重跑或旧有 52 个场景充作新包。
- 以上 100 包不等于 100 份独立真实业务盲测，公开同系列资料也具有相关性。
  缺少独立标注员和真实采购资料分布，因此不计算误导性的置信区间或总体正确率。

每包必须有独立 ID、领域、标题、来源类型、风险标签、输入文件和运行前写下的答案。
优先检查商品归属、值、单位、参数条件、三种状态；身份元数据也参加整包匹配，
但不混入业务参数分母。结果不能只检查抽出来的正确值而忽略漏掉的字段。
自定义字段保留原始语义，不要求先加入字段白名单。

## 实验纪律

1. 答案由助手按资料及产品契约编写，不调用生产归一化器生成答案；这不是双人标注。
2. 先冻结完整 fixture 的 SHA-256，再运行基线，保留完整预测。
3. 按包逐一保存运行时间、异常和结果。异常、超时、空输出不能算通过。
4. 修复阶段只查看 development 集；holdout 按风险族划分，首次运行在修复后。
   一旦用于调试就标记为已暴露，不能继续称为未见验证集。
5. 修改标注必须记录原因；同时重评旧预测与新预测，不可只修改失败用例的答案。
6. 区分错误自动确认、漏参数、漏冲突、假冲突、多余待确认；整包通过必须全输出匹配。
7. 原文、候选、事实组引用完整性另测。PDF 原件测试与结构化改编的指标分开。
8. 大批量执行应可续跑；输入、引擎或评分器变更后禁止复用旧通过结果。

## 架构决策门槛

每类失败先写最小复现与根因，再决定修复层次：输入结构、字段语义、归一化、
身份归属、事实判定、呈现/导出、测试器本身。禁止按型号、文件名、某份样本数值打补丁。

当前优先复用：字段注册表及开放字段、表格行绑定、统一身份解析、事实状态判定、
人工确认审计、原文链接、报告与导出。测试工具增强不改变公开服务接口。
不因 `engine.py` 体积大就重写；先验证能否在解析边界修复。

任何会改变候选身份、Scope 或解析结果的改动都要检查：

- 缓存签名是否需要升级，旧人工确认是否会安全失效；
- 历史 JSON 兼容、原文定位、候选去重与多商品隔离；
- CLI / 常驻服务 / Skill 安装清单是否受影响；
- 冲突选择、编辑、撤销、跳过及两种导出是否仍正确；
- 旧测试是否体现仍有效的契约，不能仅为通过而删测试。

暂不引入新的云模型、向量库、任务平台或第二套事实状态系统。
后续只有真实失败证据表明需要时，才比较更复杂的方案。
