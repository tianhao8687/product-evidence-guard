# Qoder 真实图片＋受控文档冲突验证（2026-08-05）

## 边界与授权

用户明确授权将 `samples/real` 中的匿名真实测试样本提供给 Qoder 云端宿主，仅用于
真实图片测试。本轮只使用一张已在先前单图验证中记录的公开领域标签图，以及两份
由项目生成、明确标为“受控合成”的文档；没有客户身份、账号信息、访问令牌或真实
客户正文。

`40c808ce56735a027cc990ee2e476a5b2538c538d1b20e0f6c2647182eabe7cf`。

受控文档值：

- 说明书：净重 `226.8 g`，用于与图片的 `8 oz` 做单位换算一致性验证；
- 物流表：净重 `250 g`，故意制造强冲突以验证安全拦截。

保持全部候选为 pending。

## 人工决定、导出与 stale 闭环

用户随后亲自完成了本轮决定：确认真实标签 `8.0 oz` 的重量候选，理由是它与受控
规格 `226.8 g` 换算后一致；拒绝受控物流表 `250 g` 的候选，理由是它与标签及规格
冲突。第一次导出结果为 `confirmed_count=1`、`stale_count=0`，只包含当前有效的
已确认标签重量。

为验证来源变化后的失效保护，测试操作者只改变受控测试副本的源图字节，使文件哈希
变化，再次导出。第二次结果为 `confirmed_count=0`、`stale_count=1`，旧确认没有
继续进入正式事实。测试后源图已恢复到原始哈希；这只是清理测试副本，不把已经记录
的 stale 结果改写成有效确认。

确认、拒绝、两次导出和 stale 检查均通过唯一公开入口 `scripts/run.ps1` 完成。
这个决定阶段没有调用模型、没有发起需要联网的操作，也没有向 Qoder 云端发送新
消息；本轮未做抓包。它证明的是安装副本公共入口与人工安全合同，不冒充一次新的
Qoder 云端会话或独立断网审计。完整
confirm/export/stale 录屏仍未录制。
