# v2.0.1 交付与验证记录

日期：2026-09-17。结论：面向清晰资料的本地辅助核验版本；复杂 PDF 仍不能无人复核直接作为完整事实交付。没有降低原有生产放行标准。

## 用户实际得到什么

- 仍然只看冲突、待确认、已确认；明确单一值直接确认，不要求每项补证明。采用、修改、跳过、撤销和原文入口保持在同一个处理流程里。
- 修改后的值与人工修正的商品信息贯通参数导出、授权和文案回检。无效修改就地提示，保留输入；原始资料不改动。
- 模型加载失败或内存不足时保留可读取的文字/表格结果，并说明未完成的图片/页面。资源恢复后可续跑；来源未变的有效人工决定继续沿用。
- CPU 推理最多 4 个线程，专用后台进程低优先级。预检查同时看可用物理内存和系统提交空间，但不保证原生库永远不会内存不足；不关闭用户软件、不改系统页面文件、不上传原件。
- 文字 AI 辅助保留为显式可选 `--semantic-assist`，默认关闭；`--no-semantic-assist` 可回退。图片 OCR/VLM 正常使用，不受这个开关影响。未默认加入重复提示或多轮重读。

## 改动方向与影响范围

没有新建第二套事实图、向量库或多代理工作流。复用现有 `SourceBlock → structured_rows → normalization → graph → confirmation/workflow`：

1. 数值、单位、条件与原文分开保存；人工输入不能继续被旧原文覆盖。文案回检与导出复用相同事实/比较逻辑。
2. 参数矩阵按列角色绑定，陌生条件列保留。未知字段不依赖大写与否判断可靠性；清楚的原始字段标签仍可直接采用。
3. 本地文字 AI 仅辅助少量疑难原生文本。短文保留全文，长文使用完整页/表区域及父级上下文，超过限制则不猜测。逐字复制限定词不等于理解其方向：比较符还必须通过公共数值解析器核验。
4. 新 PDF 发现的修复是通用结构问题：按字体大小确定词间距；“规格”这类列角色不进入数值；完整表头不拆成短标签和值；不同复合文字描述先要求确认，不直接认定阻断冲突。明确同单位数字不一致仍报冲突。
5. 尝试把更多型号表头直接加入身份别名后，发现会影响 SKU/型号关联并大幅增加待确认；该扩大身份推断的方案未保留。最终只共用表头识别，不改变这些字段的商品归属含义。
6. 统一回归发现开放字段的单位量级差异被过宽的“文字兼容”处理弱化。现在复用区分大小写的单位注册表与公共数值比较：`1 mW / 1 MW` 仍冲突，`1000 mW / 1 W` 不误报冲突；不靠字段名特例修补。

升级包含值语义修订 7、文字辅助修订 3。旧结果需要重新读取；人工审计仍保留，但来源或实际读取结果变化的决定会重新校验。资源暂时不可用与用户主动关闭 AI 分开处理，后者不会错误复用 AI 缓存。

最终纯文档模式与完整本地模型模式均为 22/44。这个 50% 是**所选检查点的完整自动采用覆盖**，不是全部输出准确率，也不是整份资料召回率。模型模式的文字辅助 3 次调用、0 次采用，没有在这些新原件上体现收益。

所有 103 个自动采用项另外对照了相关原页：97 项保留了该项原文信息，6 项未带全邻接/跨页条件（5 项线材、1 项适配器）。这项检查只是输出忠实度，不认证跨型号归属，更不证明未提取事实正确。两种模式仍有 2 处应提示的电流冲突没有检出。不能用这些数字宣传“97 项都已生产核验”。

最终状态数量：纯文档 103 已确认、15 待确认、0 显示冲突；本地模型 103 已确认、16 待确认、0 显示冲突。**0 显示冲突不等于不存在冲突。** Moxa、Danfoss、Arduino 的未完整读取提示与部分交付限制仍然生效。

纯文档四包墙钟之和 9.78 秒；本地模型为 372.93 秒，包含每包独立启动、图像读取与可选文字辅助，不能当成单个常驻热调用的速度。原件来源、SHA-256 和固定检查点见[冻结答案](evidence/final-public-gold-20260917.json)，逐项判断、原始阶段结果与代码散列见[原件复核记录](evidence/final-public-review-20260917.json)。测试原件和模型权重不上传 GitHub。

## 使用与回退

日常按[用户指南](USER_GUIDE.md)使用。仅把范围清楚、格式简单的资料当作辅助核验输入；重要值核对原件，复杂多型号矩阵优先提供 CSV/XLSX。已有结果升级后重新读取一次，未读完整时只能显式选择部分导出。

回退文字辅助：`analyze ... --no-semantic-assist`，图片识别保持不变。整版回退使用更新前版本 `f08356482ceb133c4d0586974b82b6b44ca9e5f2` 和对应输出备份；不要用新旧程序混写同一输出目录，不覆盖原件。

复现命令：

```powershell
.venv/Scripts/python.exe -X utf8 -m unittest discover -s tests -v
.venv/Scripts/python.exe -X utf8 tests/smoke_conversation_entry.py --entry "<installed-skill>/scripts/run.ps1"
.venv/Scripts/python.exe -X utf8 scripts/semantic_workflow_trial.py --output .runtime/new-ab --model "<existing-model>" --threads 4
.venv/Scripts/python.exe -X utf8 scripts/replay_semantic_trial.py --trial .runtime/semantic-workflow-final-20260917 --output .runtime/new-replay
.venv/Scripts/python.exe -X utf8 scripts/public_document_trial.py --manifest docs/evidence/final-public-gold-20260917.json --inputs "<originals-root>" --output .runtime/new-public
```

公开原件按清单分别存成 `<originals-root>/<case>/source.pdf`；完整模型对照加 `--model "<existing-model>"`。回答回放需要本地保留的完整实验目录。所有重跑使用新输出目录，不能覆盖首轮失败记录。
