# 简化体验与新原件正确性检查

日期：2026-09-16。结论：**入口和流程有过度工程化倾向，但当前最大的产品风险是“读取不完整却已确认”，不是功能不够多。** 本次简化了日常入口，修复了两类身份/表格绑定根因；复杂 PDF 仍不宜无人复核直接生产使用。

## 1. 什么该简化，什么不能删

| 判断 | 本次处理 |
|---|---|
| 用户首页同时暴露刷新、重读、导出模式、多个重复筛选，选择负担过重 | 默认保留处理问题、导出；低频功能收进“更多” |
| 文档把历史比赛、模型调试和当下日常操作混在一起 | README 和用户指南先讲当前使用方式；历史说明折叠保留 |
| 把所有新字段接受为参数，又把“可接受字段”当成商品身份依据 | 拆开这两个判断；参数识别继续开放，身份推断不再借开放标签制造 SKU |
| 源文件变化、冲突、撤销、文件安全、后台恢复 | 保留，这是避免误用和丢决定的必要保护 |
| 继续加更多审批层、计数门槛、模型开关 | 本轮不增加。测试包数量及代码用例通过率不能代替真实正确性 |
| 全面更换框架或重写所有大模块 | 不做。现有事实图、确认、来源定位、导出继续复用；后续应局部替换读取边界 |

目前“读取→绑定商品与条件→比较→用户处理”职责仍混有多种启发式。模块行数大只是维护信号，真正问题是不同启发式共享了不成立的假设。本轮没有新建服务、数据库、前端框架、依赖或另一套验收平台。

## 2. 用户能直接感受到的变化

- 冲突、待确认、已确认三张卡可以直接点击；移除重复状态筛选。
- 同一入口采用、修改、撤销；新增参数/商品/数值搜索；单商品不再显示无意义的商品选择。
- 页面标题说明下一步：需要处理、正在读取、可以导出，或可以先使用已确认部分。
- 按文件合并未读完的提示。排版、公式、隐藏工作表等问题提示补充资料后重读，不暗示重复点击就能读懂。
- 停止读取后继续显示“正在停止”，直到后台确认；处理中不让用户误导出旧结果。
- 选择一个已完成的商品时，不再因为另一个商品的冲突弹出无关的部分导出提示；真正的后台导出校验不变。
- 自动确认单来源、原文链接、人工修改追溯、授权边界均保留，没有变成逐条审批。

这些变化经过隐藏浏览器检查，不接管用户桌面；不代表已经完成真实用户可用性访谈，也没有自动部署到已有 WorkBuddy 安装。

## 4. 如何算分

逐项审计见[结果证据](evidence/new-originals-accuracy-20260916.json)，含每条自动确认结果的判定、原因、检查点关联及预测文件散列。

1. **自动确认项严格正确率**：可正确理解和采用的参数 / 全部自动确认项。数值、单位、归属及重要条件都必须正确；没有报错不算正确。
2. **检查点覆盖率**：116 个固定答案中，实际成为完整正确已确认结果的数量。重复结果不重复加分；原文里有答案、但采用值不完整，也不加分。
3. 允许不改变含义的文字格式差异；但不能把 byte/bit、M/m 这种改变单位含义的大小写损失当成等价。污染标签若仍明确保留参数含义，记录为体验缺陷，不一律判错。
4. 单份隔离资料包里的商品系列默认归属可以接受；明确错绑到脚注编号则判错。这不证明多商品身份能力已经完善。
5. 标准答案始终没有按预测修改。修复后测同一批资料，只叫**已暴露样本回归**，不再叫新盲测。

## 6. 根因、已修复内容及影响范围

**身份推断与开放字段耦合。** `strip_product_prefix` 原本把“后面的词能识别成字段”当成前面的数字串是型号的依据。开放字段上线后几乎任何词都满足，`MTBF1`、`M10` 被传播成整份资料的商品。现在只对已知明确参数使用这种简写推断；显式 SKU/型号声明、结构化身份和新参数提取仍开放。没有增加这些样本型号的黑名单。

**把逻辑网格误当成物理单元格。** 下部子表的列线使上部合并型号头被展开成重复值，整张矩阵被拒绝。现在只合并坐标、文本均证明是同一物理单元格的别名，不同单元格中重复型号仍不猜测。进一步发现跨行侧栏令整行 bbox 变高，取中心会读到下面一行，已改为实际水平行带定位。

同一个纵向合并参数标签可能包含阈值和恢复行为，不能拆成彼此冲突的两个“值”。目前未完整绑定的这种区域留作一条资料读取问题，而非制造假冲突。拆分子表也继续保守报告，不做盲目填值。

修改集中在原有提取器、共用表格绑定及 PDF 几何适配层；CSV/DOCX/XLSX、显式 SKU、多商品归属和旧 PDF 均在回归影响范围内。旧代码复用，不改变事实/决定的数据结构。引擎缓存修订已更新，避免把旧提取结果继续当成修复后结果。原件和人工决定不被直接改写。

## 7. 尚未解决，而且比增加功能更重要

| 问题 | 实测表现 | 应走的方向 |
|---|---|---|
| 一行被当成完整事实 | Pico CPU 少频率、生命周期少日期、无线能力少“仅 W 版”条件 | 先绑定完整段落/单元格与续行，再产出事实 |
| 双栏或相邻图文串接 | E91 标签混入图纸标题，SAM-M10Q 把左侧句子接到右侧参数 | 按区域阅读，禁止跨栏拼接；不加厂商字符串补丁 |
| 单位信息被通用文本清洗破坏 | GB、KB/MB、MΩ、MHz 等被小写化 | 原文展示值与用于比较的语义值分离；仅对理解的单位做换算，不对所有字符串统一 casefold |
| 重要脚注与坐标轴未保留 | 保修条件、TBW 测试方法、尺寸 W/H/D 等缺失 | 将适用条件作为结构字段随值传递，不只留在隐藏原文里 |
| 没有补齐缺口的模型调用 | 多花约 9 分钟，首次覆盖仍是 17/116 | 仅把无法绑定的区域连同表头/条件交给模型；完整回读后再采用 |
| 信息碎片冒充参数 | 图片标题、型号自复制、营销句片段进入已确认 | 用完整参数关系约束输出，而不是退回固定字段白名单 |

其中单位展示/比较分离会影响分组、去重、冲突、人工决定匹配及内容回检，不能只改显示字符串就宣称修好。本轮把它如实计为错误，没有临时放宽标准来做高成绩。

补充的独立数值探针进一步确认：现有已知 `power` 归一化把 `1mW` 和 `1MW` **都算成 `0.001 W`**，而后者应为 `1,000,000 W`；开放字段也把两者都变为 `1mw`。这不是单纯界面大小写问题，而是会漏掉冲突的高优先级根因。该探针记录在结果证据中，未计入官方原件得分，也没有声称已修复。下一步必须统一处理大小写敏感单位和未知单位的安全回退，而非仅替换几个显示标签。

推荐后续只围绕“**一个可靠读取区域 → 完整参数、归属、条件 → 现有事实图**”局部重构。保留规则读取清楚文本，困难区域按需用模型；后台执行严格，界面仍只显示三状态。是否晋升自动确认取决于值是否读完整，不取决于堆了多少条证据或审批记录。

历史 4 份官方原件兼容性复测均运行完成，原明纬 18 个定向参数检查仍为 18/18；另外 3 份只是兼容性/运行检查，不伪装成独立正确率。依赖证据检查通过，未新增依赖。新样本不混入此前 100 包合成/公开改编样本的“首次”统计。

复现环境为项目锁定依赖，Python 3.11。通过上述官方链接获取相同散列的 PDF；若厂商替换了文件，应记录新版本，不能套用旧答案。每份文件单独放入目录。
