# 五批生产化改造：统一验收结果

结论：五批代码改造完成，随后统一测试、定位根因和复测。**当前可用于受控本地试运行，尚不具备全面生产放行证据。** 655 项回归成功执行，其中 652 项通过、3 项跳过；这不是商品参数正确率 100% 的证明。

## 用户能看到的变化

- 仍然只有冲突、待确认、已确认；明确且无争议的单来源参数可以自动确认。
- 文件没有读全时按文件/表格集中提示，不把每个漏读位置变成待确认参数。
- 默认导出检查完整性；可以明确选择只导出已确认部分，表格与简报会携带未完成说明。
- 后台任务可以取消、恢复，已完成且原件未变的文件可复用；更新失败保留上次结果并明确提醒。
- 旧版结果和人工决定保留，但旧结果需重新读取一次，才能通过新版完整交付检查。

## 五批范围与根因修复

| 批次 | 实际完成 |
| --- | --- |
| 1. 支持范围 | 明确 Windows 本地单用户范围、验收要求、升级和回退方式 |
| 2. 原件结构 | 保留 PDF 几何位置，复用 CSV/Office 的商品矩阵绑定和父级条件；无法可靠对应的区域明确报出 |
| 3. 简单操作 | 页面、参数表和本地简报共用完整性检查；事实状态与读取缺口分开 |
| 4. 运行保障 | Office 输入限制、来源前后校验、文件级检查点、报告发布恢复、任务取消与重复请求处理 |
| 5. 验收准备 | 新增回归、公开原件检查、离线验收工具、依赖清单和本地试运行文档 |

没有另建事实引擎或任务平台；继续使用原有事实图、来源散列、人工审计和缓存。

统一测试发现并修复的共享根因包括：

- 表格先打平导致型号、父级条件丢失：改为保留行列和实际合并单元格，再交给同一个绑定器。
- PDF 近水平细线被误认成竖线：按几何方向归一化，不为某个供应商增加字段白名单。
- 开放字段提取影响原有 `INPUT: 5V/3A` 复合参数：保留开放标签，同时复用有明确口径的既有电气解析。
- 只检查产生候选的文件会漏掉其他来源变化：加入整批来源清单和零候选文件快照校验。
- 取消或写入中断可能留下不一致状态：取消只处理本次任务拥有的进程，报告恢复到上一个完整版本。

## 仍未完成的生产条件

1. 无边框、多层表头、多型号/测试条件混排的 PDF 仍有读取缺口。例如太阳能参数的 STC/NMOT 分组和部分条件模式，尚不能保证完整绑定。当前处理是明确提示、允许带范围说明的部分交付；不是声称这些内容已经读懂。
2. 尚没有达到本轮放行标准的 60 包原件、15 家供应商、10 领域、3,000 条独立人工复核事实，也没有新的冻结留出集。机器自评或这次增加的代码测试不能补足这些证据。
3. 尚无真实用户试用签认和目标机器持续批处理稳定性签认。本次短时模型复测与故障注入回归不能代替长期运行。

[放行清单](evidence/production-acceptance-manifest.json)有意保留空的独立证据项，因此检查报告包含 10 项未满足的门槛。代码回归结果已记录，但没有冒充独立签认。本次也没有自动部署到已有 WorkBuddy 安装或宣称 GitHub CI 已通过。

当前可以试用的范围与升级方式见[本地试运行手册](LOCAL_TRIAL_RUNBOOK.md)。遇到上述布局，优先补充明确表头的 CSV/XLSX 或原图；不要把“仅已确认部分”当成完整商品资料交付。

## 复现

在已安装锁定依赖的项目环境内运行：

```powershell
python -m unittest discover -s tests -v
node tests/check_simple_review_browser.cjs
python scripts/generate-sbom.py --check
python scripts/check_native_layout.py --originals <四份原件目录> --output <独立结果目录>
python scripts/production_acceptance.py docs/evidence/production-acceptance-manifest.json --output .runtime/production-acceptance.json
```

浏览器脚本需要 Playwright 与可用浏览器。原件目录使用 `meanwell.pdf`、`tplink.pdf`、`solar.pdf`、`noctua.pdf` 四个名称，脚本校验固定原件散列；生产放行清单缺少证据时返回退出码 2 是预期行为。验收脚本和 JSON 证据保留在源码仓库中，不随精简的 Skill 运行包安装；安装包仅附说明文档。私有资料包及完整日志不提交仓库。
