# 原件读取、简洁审核与新增原件测试

## 结论

本轮修复了若干共性读取问题，保留“清晰单来源直接确认”的体验，没有增加用户必填步骤。
但新原件测试仍暴露明显漏读、条件丢失和假冲突。**当前仍是受控本地试运行版本，不应宣称任意 PDF 都能可靠自动核验，尚未生产放行。**

原有结构化资料包测试通过，不等于复杂原始页面读对。此次测试把这个缺口单独量化，失败资料未剔除。

## 用户能看到的变化

- 主界面仍只分冲突、待确认、已确认。普通单来源明确参数仍自动确认。
- 双栏中的无关清单不再直接接到另一栏的参数后面；一个完整参数中的冒号、分号不再随意拆成新参数。
- 参数附注条件保留到采用值/适用范围；主卡片简写为“含附注条件”，展开可看全文，并直接打开附注所在原页。
- 长条件在主卡片缩略，完整内容留在详情。采用、修改、撤销仍用现有入口。
- 某些无法可靠对应行列的表格，集中报一次读取问题，不伪造大量冲突或待确认参数。读取不全依然限制完整交付，允许用户明确选择部分导出。

## 根因与局部修复

| 根因 | 本轮处理 | 仍未解决的边界 |
| --- | --- | --- |
| 按整页文字顺序拼接，越过左右栏 | 使用实际单元格/打印分隔线；行内值止于本文字区域 | 无边框且多层嵌套的矩阵仍可能漏读 |
| 完整单元格被冒号、分号拆碎 | PDF、Office、CSV 复用完整参数分段契约 | 普通长段落还不能保证语义完整 |
| 背景矩形被当成表格边框 | 排除未描边背景，保留实际细线；补绑定缺上边框的表头 | 符号、数学公式、子行对应仍有限 |
| min/typ/max、条件、单位被当成独立商品字段 | 按明确表头角色合成参数行，保留各列值和条件 | 同一格内多组测量先报读取问题，不能猜测映射 |
| 修订记录、引脚清单、无归属记录表产生假冲突 | 区分表格用途；未确定记录归属的表格不直接扁平化 | 中英重复章节、认证工况、联络信息仍有误识别 |
| 上下标、跨页脚注丢失 | 按字形位置读取；精确标记关联附注；歧义不静默丢弃 | 全表标题条件、复杂数学下标和正文 Note 引用尚不完整 |
| 浮动的 “Model Code” 被认成型号 Code | 未绑定的正文标题不能充当商品身份 | 多容量/多型号矩阵还需明确列级归属 |

复用现有 `SourceBlock → StructuredCell → FactCandidate → FactGroup` 流程，没有新增服务、数据库或供应商模板框架，也没有把未知参数挡在固定字段白名单外。
读取语义版本升级为 3，旧解析缓存需要重读；既有人工决定继续按原审计和来源失效规则管理。
安装清单同步包含新增附注模块。

## 统一验证与本地模型

最终回归数量、日志哈希、每份预测哈希、各检查点判读和代码指纹见[机器可读验收记录](evidence/region-reading-validation-20260916.json)。

- 完整回归：714 项，711 通过、3 项因 Windows 符号链接权限跳过，0 失败；196.326 秒。
- 较本轮开始新增 34 项回归测试；中途发现的安装漏项和数字项目符号退化均修复后重新执行完整回归，未把失败测试删除。
- 15 份原件最终运行均无引擎运行错误，但这不代表内容正确。新 10 份的冲突输出由 44 组减到 21 组、待确认由 34 组减到 29 组，仍含假冲突。

后台浏览器检查覆盖采用、修改、撤销、不使用、授权与内容回检、四种宽度、6000 项分页及失败更新提示；新增附注预览检查。没有操控用户正在工作的前台窗口。

真实 Qwen3-VL-8B INT4 OpenVINO 模型在 CPU、低优先级、4 核限制下运行了 E91 原件，实际完成 1 次混合页视觉处理，无运行错误。
其中一次记录为 132.721 秒，结果是 10 项已确认、2 项待确认；原生读取同资料为 10 项已确认、1 项待确认。
这说明本次模型冒烟测试跑通，但**这一份资料没有增加自动确认事实**；不能从单例推出模型总体无效，也不能把加载成功当成正确率通过。
最后一次数字项目符号回归修复发生在该模型运行之后，未改变模型/视觉推理代码；最终原生原件和完整回归另行执行，记录中明确区分代码指纹。
墙钟时间来自后台共享机器，不是受控性能基准。

## 尚不能放行的具体原因

1. 五份新原件在预登记检查点上仍是 0/8。旧样本改善不能代替新模板适配。
2. 多语言重复章节、认证试验工况仍产生假冲突；不能把冲突总数减少直接当成冲突准确率提高。
3. 原文标题/全表条件、数学下标和多层合并单元格仍可能损坏采用值的含义。
4. 本轮原件判读由代理完成，不是独立人工验收；正式业务放行记录仍未填写。

最有效的下一步是完善“单元格内部子行 + 表头/章节条件 + 型号列”的统一绑定，并在这些既有失败原件上回归，再由独立人员检查新的原件。
不宜继续靠添加字段名字或提高确认阈值来补，也不宜先扩展更多界面功能。
当前可受控试用清晰参数表/明确键值资料；复杂说明书需要人工复核或补充结构化资料，不提供无条件自动交付承诺。
