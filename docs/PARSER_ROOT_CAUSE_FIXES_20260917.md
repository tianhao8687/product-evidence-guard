# 三项提取问题的根因修复

日期：2026-09-17。承接上一批人工修改、导出、回检一致性修复；本文保留当时分批验证结果，现随 v2.0.1 统一交付，见[最终验证](STABLE_DELIVERY_20260917.md)。

## 结论与范围

这三个问题不是缺少某个供应商名或某个参数名，而是解析阶段过早丢失了信息。修复保留现有读取、归属、事实分组、人工决策和导出流程，没有增加新的服务、模型或用户操作步骤。

### 1. 限定语被丢掉

根因：数值解析器找到“数字 + 单位”后，只检查剩余内容有没有数字或少数运算符；剩余文字被当成装饰忽略。于是“非 80g”“约为 80g”也可能变成普通 80g。文案核对和复合输入/输出参数还有各自截取数字的路径。

修复：

- 单值、范围、容差、尺寸都检查完整表达式。未解释的文字或符号保留为无法可靠解析的原文，不自动确认。
- “不能超过”保留上限，“约为／大约为／approximately”保留近似含义。支持常用表达不再意味着未知表达也能偷偷通过。
- 已有字段标签、合法的电网频率附注和尺寸轴顺序仍可解析；不同单位的等价双写保持兼容。
- 复合电参数有未解释内容时，整句不能凭其中几个数字通过。
- 文案核对保留完整值，并检查字段前未解释的限定，不能仅凭局部数字匹配通过。IP 简写也检查前后限定。
- 不认识的单位大小写组合在范围、容差中安全返回待核对，不抛异常。

### 2. 参数表忽略商品列和陌生条件列

根因：参数矩阵被优先识别为“参数／值／单位”表，随后固定生成空商品身份，且只有列在条件词表中的列才被保留。改个列名就可能改变事实归属或制造冲突。

修复：

- 按列角色处理参数、值、单位、SKU、型号和变体；行归属复用已有身份处理函数。
- 其余非空列均作为上下文保留，不再以是否在条件白名单内决定是否丢弃。
- 通用条件标题使用一致的上下文形式；陌生维度保留“列名：值”，避免不同维度同名值被混为一谈。
- 数值列与条件列分开进入解析；原文行仍完整保留。条件进入适用口径，清楚的单来源参数继续自动确认。
- 缺失的行身份、互相矛盾的身份列不会猜成另一个商品；0 值和 0 条件不会被当作空白。
- CSV、XLSX、DOCX 和原生 PDF 表格共用 `StructuredCell.provenance`，减少各读取器重复拼装元数据而漏列的机会。

### 3. 数值在前的陌生参数由大小写决定是否识别

根因：“全大写”同时充当了字段识别规则和语义可靠性的证明。结果 ROM／Rom／rom 不等价，ERRORS 却可能被自动批准。

修复：

- 数值在前的短字段名不区分大小写识别，单位符号仍区分大小写。
- 识别出一个可能的字段，不等于已经证明它就是参数。孤立的陌生短句先保留为待确认。
- 同商品、同字段、同口径有明确字段绑定或人工确认，即可确认字段含义；不要求第二份来源文件。
- 字段绑定与数值投票分开：明确字段若给出不同值，仍进入冲突；重复多少条模糊短句也不能自证。
- 普通“字段：值”、明确表格和已有数值字段不受这一收紧影响。

这是一个有意调整的边界：不能保证任何陌生短句都自动理解。支持更多大小写形式，也不应把所有“数字 + 单词”的正文都确认为商品参数。

## 相关一致性修复

- 汇总中的冲突、待确认、已确认计数均来自事实状态，并在人工处理后重新计算。
- Markdown 明细按事实状态排序、命名，不再把自动确认的单来源事实显示成 `insufficient_evidence / review`。
- 证据级 `pending` 显示为“未人工操作”，与事实级“待确认”区分。
- 原有证据比较分类仍保留在数据中，不进行破坏性模型迁移。
- 值语义版本由上一批的 5 升至 6，分析缓存随之失效；旧结果需要重读。人工决策审计保留，证据或解释发生变化的决定按既有快照规则失效。

## 验证设计

新增 `tests/test_parser_contracts.py`，最终包含 16 个测试方法及多组子用例，覆盖不同数值、前后限定、范围／尺寸、复合电参数、大小写变换、陌生字段、明确字段与冲突、重复模糊短句、人工确认、跨格式归属、条件列改名、空身份、身份矛盾、0 值，以及人工处理前后两份汇总一致。

这些是带明确预期的缺陷回归和变形测试，不是新增真实业务盲测，不作为项目整体准确率。

旧测试的预期有三处有意调整：全大写孤立短句不再凭大小写自动确认；参数矩阵不再丢弃 Symbol 列；证据级“待人工确认”改成“未人工操作”。原本正确的明确参数、单位换算、冲突、安全导出等预期没有放宽。

验证结果（按执行顺序）：

- 修复前的首批 11 个新测试方法触发 55 个失败断言／子用例，确认缺陷可复现。
- 主体修复后的全量回归：760 个测试，757 通过、3 跳过，0 失败、0 错误，耗时 307.108 秒。
- 随后补充“字段前限定语”保护及跨格式来源断言，相关提取、归属、人工操作、授权文案核对 88 个测试全部通过，耗时 37.197 秒。这是最后小改动的相关回归，不另算一次全量测试。
- 最终新增文件中的 16 个测试全部通过，耗时 2.137 秒。
- 最终无窗口 Edge 交互回归通过：采用、无效修改就地提示、有效修改、撤销、跳过、授权、文案核对、4 种窗口宽度、6000 条事实分页、读取时导航、失败提示。
- `git diff --check` 通过。
