# 100 包跨领域测试与架构决策

日期：2026-09-16。阶段性结论：结构化资料包的本轮缺陷已修复并通过整包复测；
**复杂原始 PDF 尚未达到通用发布要求，不能把 100/100 解释成产品准确率 100%。**

## 1. 实际测了什么

100 个独立 ID、独立输入定义的资料包，10 个硬件/工业细分领域各 10 包。
20 包来自厂商公开参数选摘、翻译或格式改编；80 包为领域化虚构压力场景。
主要输入格式是 TXT、CSV、JSON，不是 100 份原始 PDF、独立客户资料或人工双盲样本。
同厂商同系列的两个改编包具有相关性，不能当成两个独立供应商。

| 领域 | 包数 | 公开改编 / 虚构压力 | 原资料例子 |
|---|---:|---:|---|
| 工业电源 | 10 | 2 / 8 | MEAN WELL LRS-35 |
| 网络设备 | 10 | 2 / 8 | TP-Link TL-SG105 / 108 |
| 机械传动 | 10 | 2 / 8 | Pololu 37D 减速电机 |
| 电池储能 | 10 | 2 / 8 | Victron 12.8V 锂电池 |
| 散热通风 | 10 | 2 / 8 | Noctua 风扇 |
| 光伏组件 | 10 | 2 / 8 | Canadian Solar CS6R |
| 环境传感 | 10 | 2 / 8 | Sensirion SCD41 / SHT31 |
| 电动工具 | 10 | 2 / 8 | Makita 电钻 |
| 胶粘材料 | 10 | 2 / 8 | 3M VHB 胶带 |
| 计量仪器 | 10 | 2 / 8 | Fluke 仪表 |

每包保留来源 URL、原始型号、改编说明、风险标签、输入与显式标准答案。
未知字段、条件/单位混淆、模型/变体归属、JSON 嵌套、版本、模板纠错、科学计数法、
编码与 CSV 方言、真冲突、表达不确定等有不同组合，不只是循环替换数值。
输入变形回归、原件探针和旧中文资料包均另计，不填充 100 包数量。

可读编排在 `tests/fixtures/cross_domain_100.py`，冻结输入与答案在同名 JSON。
执行前协议见 [TEST_PHASE_100.md](TEST_PHASE_100.md)。

## 2. 评分与实际结果

整包必须同时匹配商品归属、字段、口径、状态、完整值和单位；多提、漏提、重复预测
都影响通过。SKU 等身份元数据参加整包检查，不混入业务参数分母。
另查来源文件哈希、候选与事实引用、采用值归属。超时、异常、空语料不能算成功。

| 阶段 | 通过包数 | 与答案不一致的已确认参数 | 缺少的事实键 | 需处理参数 |
|---|---:|---:|---:|---:|
| 修复前 development，以统一修订评分重评旧预测 | 61 / 80 | 13 | 28 | 15 |
| 修复后 development | 80 / 80 | 0 | 0 | 9 |
| 首次 holdout，以统一数值容差重评 | 20 / 20 | 0 | 0 | 1 |
| 最终整批重跑 | 100 / 100 | 0 | 0 | 10 |

最终 295 个业务事实：**285 已确认、7 待确认、3 冲突**。这批资料中无漏冲突、
假冲突或无必要待确认；不代表其他分布也为零。只有 3 个真冲突事实，安全边界样本
仍不够充分；620 余项回归不能简单合并成更多独立业务样本。

上表“13”包含字段规范/口径错配，不等于 13 个错误物理数值；“缺少事实键”与
该列也可能重叠，不能相加为独立缺陷数。更少待确认不是单独的质量目标，必须同时
约束漏读和错误自动确认。

初版评分为 development 57/80、holdout 19/20。两处 gold 契约错误、排版等价与
温度浮点尾差经过记录后修订；旧预测和新预测一起重评，没有把评分修订当作引擎进步。
细节见 [标注与评分修订日志](evidence/cross-domain-100-annotation-log.md)。
holdout 为胶粘材料、计量仪器两个完整领域，首次运行在开发修复后；现在已查看，
后续只能称回归集。所有答案由助手标注，没有独立复标或总体统计推断。

## 3. 根因修复，不按商品打补丁

| 根因 | 实际修复层 | 为什么能复用 |
|---|---|---|
| JSON 展平丢掉对象边界，参数可能继承错误商品；重复键最后值覆盖前值 | 对象级身份边界，复用表格的身份冲突判断；重复键/非有限数拒绝 | 不按 JSON 键顺序、型号或供应商写特例 |
| 表头把所有括号都当单位，丢掉 STC、温度、含电池等条件 | 共用 `split_label_unit`，只剥离真单位，未知条件保留在字段身份中 | 表格与明确标签共用，不分别修 CSV/XLSX/DOCX |
| 口径识别依赖数值正则，带单位表头/未解析值丢失输入输出、额定语义 | 从明确标签独立确定口径，再解析值 | 复用注册表 Scope 与既有身份/图逻辑 |
| Windows CRLF 使分号 CSV 的方言检测失败，回退逗号后静默漏项 | 仅检测时归一行尾，读取仍用原字节含义 | 解决解析入口，不在提取器猜“这行本来是 CSV” |
| 提前按分隔符拆句，把模板/否定纠错句拆成看似正式的参数 | 共用幂等分段函数，先识别模板与纠错边界 | 引擎与提取器不各自维护一套拆分规则 |
| 合法科学计数法、微安缺少统一支持 | 有界数值语法、单位注册表；异常指数不膨胀为巨大整数 | 归一化层一次实现，不逐字段增加正则 |
| 共享固定容差可能吞掉 0.5 微安差异；列表换算尾差可能制造差异 | 共享数值比较区分真实差异、浮点尾差、布尔/非有限值，递归比较有序列表 | 图、人工选择、视觉一致性和内容回检都复用原函数 |
| PDF 文字层与 OCR 的范围/公差符号空格不同 | 开放值只归一排版空格，保留边界、运算符、单位与尾部条件 | 陌生字段无需添加业务白名单；不同湿度、凝露条件仍不同 |
| 测试器的精确浮点串比较、检查点瞬时占用、纯原件输入缺省键 | 独立单对单数值评分，复用原子写入并有界重试，原件哈希/路径检查 | 修评测基础设施，不让测试故障变成商品缺陷 |

此外去除了重复 `_HEADERS` 视图和失去对象语义的私有 JSON 展平实现。
旧 `n18` 科学计数法预期明确升级，未删失败用例；模板、微小电流差异、范围排版、
JSON 键置换、异常数值、超时与续跑均有额外回归，不能算作更多新资料包。

## 4. 原始 PDF：发现了尚未解决的主问题

4 份官方原件另外运行了文字解析与实际本地 OCR/Qwen3-VL，未使用云推理。
源文件前后 SHA-256 一致。下列计数只是程序输出，**不是正确事实数或完整准确率**。
初次本地模型运行早于末尾的文档标题过滤/排版修复，保留为诊断基线，不冒充最终版本成绩。

| 原件 | 初次本地模型耗时 | 输出：已确认 / 待确认 / 冲突 | 核心问题 |
|---|---:|---:|---|
| [LRS-35 电源](https://www.meanwell.com/Upload/PDF/LRS-35/LRS-35-SPEC.PDF) | 69.60 s | 10 / 1 / 1 | 6 型号参数矩阵漏读；不同保护类型失去父级条件被当成冲突 |
| [TP-Link 交换机](https://static.tp-link.com/res/down/doc/TL-SG105_V2_Datasheet.pdf) | 254.99 s | 4 / 4 / 1 | 型号列绑定缺失；文字/OCR 排版空格造成假冲突 |
| [CS6R 光伏](https://static.csisolar.com/wp-content/uploads/2020/06/27131418/CS-Datasheet-HiKu6_CS6R-MS_v2.0_EN.pdf) | 70.68 s | 8 / 3 / 1 | STC/NMOT 是测试条件，不是同参数冲突；型号矩阵仍漏项 |
| [Noctua 风扇](https://cdn.noctua.at/media/noctua_nf_a8_pwm_infosheet_en_web.pdf) | 162.27 s | 1 / 3 / 0 | 标签/值跨列；单包装与整箱重量失去层级 |

最新纯文字解析重跑：电源 5/0/1、交换机 6/0/0、光伏 8/2/0、风扇 0/0/0。
标题过滤消除了部分假事实，但没有恢复丢失矩阵；风扇零冲突也绝不代表正确完成。
交换机排版修复后，真实模型复测约 270.78 秒，输出 5 已确认、4 待确认、0 冲突；
范围空格假冲突已消除，但型号矩阵漏读未解决。与回归测试并行运行，不能作为严谨
的速度前后对照，仍须检查完整性而非只看冲突数。

根因是 `parse_pdf_document` 将页文字拆成独立行，行列、合并单元格、父表头与商品
对应关系没有进入后续证据合同。已经丢掉的结构，不能靠扩充字段名可靠恢复。
在原件上找到的空格假冲突已作通用修复；型号矩阵与层级问题**尚未修复**。

## 5. 方向比较与重构决定

| 路线 | 收益与代价 | 决定 |
|---|---|---|
| 继续补字段、供应商和型号正则 | 快，但恢复不了列归属，样本外继续漏读或错配 | 不作为主路线 |
| 整页反复调用或直接更换大模型 | 当前本地通路已耗时较高且仍漏读；更大模型没有本机对照证据 | 不直接加调用量，不宣称换模型必然有效 |
| 先保留坐标、单元格、父表头，转成已有结构化证据；只对疑问区域用视觉 | 最接近信息丢失根因，可继续用现有身份/图/确认/导出 | 优先做受控适配层验证 |
| 重写 engine、graph、审核与导出 | 影响人工决定、缓存、宿主接口与已有交付，未见相应收益证据 | 本轮不做 |

已做只读可行性探针：使用现有依赖环境中的 pdfplumber 0.11.9 去重字形与默认表格
检测，4 文件各约 0.98～2.22 秒。电源页能保留 33 行 × 7 列，交换机页能保留
18 行 × 3 列；但电源 MODEL 表头在默认表格边界外，光伏/风扇无框表没有正确恢复。
绘图线条也会被检测成小表。**这只证明部分几何结构可恢复，不是端到端提取速度或
准确率对比，更不是安装一个库就解决问题。** 未增加生产依赖或把该探针接入主流程。

拟议适配层先只接收可解释的行列映射：坐标去重 → 单元格/父表头 → 结构化事实证据。
横向型号表需有可验证表头才转置；不猜型号，不将合并空格盲目向右填充。
一张页里已处理的表区与普通文字区需去重，无法绑定的区域给出文档级读取提示，
不能静默丢掉，也不制造几十项毫无意义的待确认。

## 6. 影响范围与保留/淘汰

本轮保留：专业字段注册表、开放字段 ID、表格单元格证据、统一身份、事实图、
三状态界面、人工操作审计、原文链接、两种导出、模型常驻与来源只读。
不新增用户配置项、向量库、云服务、第二套审核状态或另一条宿主入口。

| 影响点 | 本轮处理 / 后续门槛 |
|---|---|
| 缓存、候选 ID、人工决定 | 分析修订升为 `v6-structured-label-context-20260916`，规则指纹更新；旧解析不静默复用，决定继续按候选/来源哈希校验 |
| JSON / 表格归属 | 共享身份歧义合同；键顺序不影响归属，嵌套明确商品不继承父 SKU；保留 JSON 路径追溯 |
| 数值比较 | 影响图、选择、回检和视觉一致性；新增微安差异与列表尾差测试，重跑旧闭环 |
| 接口、安装清单 | 未新增生产模块或依赖，公开 CLI/服务/Skill 操作合同不变；本轮不重装宿主或弹出窗口 |
| 文档 | 修正“白名单封闭、所有项目人工确认、顶层永远 pending”等过时描述；历史性能/发布记录保留日期，不改写历史证据 |
| 将来的 PDF 适配层 | 必须验证页/框原文链接、去重、跨页表头、合并单元格、资源限制、缓存失效与旧确认；新增依赖须重锁依赖与许可证/安装验收 |

一个旧文档测试把历史 Mermaid 的行号当永久契约，新增说明就失败。现改为保留
历史审计不动、比较图清单并继续检查当前语法结构，不把行号变化当功能破坏。
它仍只是静态检查，不冒充渲染验证。

## 7. 回归与剩余门槛

最新整包运行：100/100，295 个业务事实，约 16.84 秒；仅确定性资料路径，
双工作进程，每包隔离，90 秒超时，不代表模型路径的速度。
既有中文资料包在全部生产修复后用真实本地模型重新运行约 88.77 秒，130 条证据、62 组事实
（57 已确认、4 待确认、1 冲突），与上轮候选/事实语义完全一致，原件未修改。
该回归不是新盲测；此前中间版本另跑过约 83.04 秒，原始结果也保留。

最终完整单元/集成回归：**623 项，224.321 秒，0 失败、3 项跳过**；跳过项均为
当前 Windows 无创建符号链接特权，不能写成这些路径已实测通过。
次数、跳过原因、运行日志哈希与逐包预测见
[机器证据摘要](evidence/cross-domain-100-20260916.json)；原始 PDF 无完整整篇 gold，不计算
伪精确的原件准确率。临时原文、模型与私有输出保留在被忽略的 `.runtime`，
公开证据只放摘要、公开改编/虚构预测，不包含用户文件名与正文。

进入下一阶段的门槛：

1. 为原始矩阵/无框表/父表头/包装层级建立完整标注，重点增加真冲突和安全负例，
   独立复标后再谈总体正确率；覆盖至少一家未参与调试的新供应商。
2. PDF 适配层逐页显示已处理/未处理区域；同时比较遗漏、误确认、假冲突与用户操作数。
3. 在旧流程没有回归、原文定位与缓存迁移正确后，再决定是否替代旧解析路径。
4. 新增跨页、扫描模糊、长文档、异常格式和资源超限资料；扩展硬件以外领域。

本轮完成了 100 包的建立、执行、可定位根因修复和回归，不代表所有发现的问题
已经修完。**原始复杂 PDF 的发布门槛未通过，保留为明确 P0，不建议直接全面发布。**

## 8. 复现

```powershell
.venv/Scripts/python.exe scripts/evaluate_corpus.py --output .runtime/my-corpus-run --workers 2 --timeout 90
.venv/Scripts/python.exe -m unittest discover -s tests -v
```

中断后在同一命令加 `--resume`；输入、答案、引擎或评分器变化时应新建输出目录，
旧检查点会拒绝复用。`report.json` 包含逐包完整预测、来源组成、领域和错误分类。
纯原件测试通过 `native_files` 的相对路径/哈希与 `--native-root` 接入；原件自行
从记录的官方 URL 获取，不把第三方完整文件打入仓库或本轮资料包。
